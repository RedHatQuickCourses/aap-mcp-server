= Section 4: Communication Workflow

== The Full Journey: From User to AAP

Let's trace exactly what happens when you ask the AI a question. This is the **complete communication workflow**.

== Step-by-Step Breakdown

=== Step 1: The User Initiates a Request
[source]
----
You: "Show me failed jobs from the past 7 days"
----

This is a natural language request sent to your AI tool (Claude, Cursor, ChatGPT, etc).

*What's happening*:
* The AI client receives your message
* It sends it to the AI model for interpretation

=== Step 2: The AI Model Interprets and Plans
[source]
----
AI Model (thinking):
"The user wants:
1. A list of jobs
2. Filtered to only FAILED status
3. From the last 7 days

I need to call the job_list tool with:
- status = "failed"
- limit = 7 days
"
----

*What's happening*:
* The AI model understands your intent
* It maps your request to available MCP tools
* It prepares the structured request with parameters

=== Step 3: The MCP Server Receives the Request
[source]
----
Request from AI:
{
  "method": "tools/call",
  "params": {
    "name": "job_list",
    "arguments": {
      "status": "failed",
      "limit_days": 7
    }
  }
}
----

*What's happening*:
* The MCP server receives a structured tool call
* It validates the request format
* It checks that the tool exists

=== Step 4: The MCP Server Authenticates
[source]
----
MCP Server checks:
✓ API token is valid? YES
✓ Token belongs to active user? YES
✓ User has read permission? YES

Status: AUTHENTICATED
----

*What's happening*:
* The MCP server extracts your API token from the request headers
* It verifies the token with AAP
* It loads your user's permissions and RBAC settings

=== Step 5: The MCP Server Translates and Calls AAP
[source]
----
MCP Server translates to AAP API call:
GET /api/v2/jobs/?status=failed&created__gte=2024-09-08

Headers:
  Authorization: Token <your-aap-api-token>
  Content-Type: application/json
----

*What's happening*:
* The MCP server converts the tool call into an AAP API request
* It uses your API token to authenticate with AAP
* It applies any RBAC restrictions from your user account

=== Step 6: AAP Executes the Query
[source]
----
AAP Database Query:
SELECT jobs WHERE status='failed' AND created > '2024-09-08'
RESULT: 3 failed jobs found
----

*What's happening*:
* AAP queries its database
* It applies your user's permission restrictions
* It only returns jobs you're allowed to see
* It returns the results as JSON

=== Step 7: The MCP Server Standardizes the Response
[source]
----
Raw AAP Response (200 JSON objects with 50 fields each):
{
  "count": 3,
  "results": [
    {
      "id": 456,
      "name": "Deploy Config",
      "status": "failed",
      "created": "2024-09-10T14:32:00Z",
      "started": "2024-09-10T14:32:05Z",
      "finished": "2024-09-10T14:45:00Z",
      ...50 more fields...
    },
    ...
  ]
}

MCP Server Standardizes:
{
  "jobs": [
    {
      "id": 456,
      "name": "Deploy Config",
      "status": "failed",
      "duration": "12 minutes",
      "failure_reason": "Host unreachable"
    },
    ...
  ]
}
----

*What's happening*:
* The MCP server receives raw AAP data
* It extracts only relevant fields
* It formats data in a way the AI can easily understand
* It simplifies complex structures

=== Step 8: The AI Model Processes the Data
[source]
----
AI Model receives standardized response
AI Model thinks:
"I have 3 failed jobs. Let me summarize them for the user
in a clear, readable format"
----

*What's happening*:
* The AI receives the structured data
* It reads and understands the job details
* It composes a human-readable summary

=== Step 9: The AI Client Displays the Response
[source]
----
You see in your AI chat:

"You have 3 failed jobs from the past 7 days:

1. Deploy Config (Job #456)
   - Duration: 12 minutes
   - Status: FAILED
   - Reason: Host unreachable
   - Started: Sept 10, 2:32 PM

2. Database Migration (Job #457)
   - Duration: 25 minutes
   - Status: FAILED
   - Reason: Permission denied
   - Started: Sept 11, 10:15 AM

3. Cleanup Tasks (Job #458)
   - Duration: 5 minutes
   - Status: FAILED
   - Reason: Timeout
   - Started: Sept 12, 3:45 PM
"
----

*What's happening*:
* The AI client displays the formatted response
* You read the summary
* You can now ask follow-up questions

== Key Insights

=== Security Checkpoints
The workflow has **multiple security checkpoints**:
1. ✓ Token validation (is the request from a valid user?)
2. ✓ RBAC check (does the user have permission for this action?)
3. ✓ Data filtering (only show data the user is allowed to see)

=== Data Flow
Data flows in **two directions**:
1. **Request direction**: Natural language → Structured tool call → API call → Database query
2. **Response direction**: Database result → Formatted response → Natural language summary → Display

=== No Direct AI-to-AAP Access
**Important**: The AI model never talks directly to AAP.

The MCP server is always in the middle:
* ✓ The AI cannot bypass authentication
* ✓ The AI cannot exceed user permissions
* ✓ All requests are logged and auditable
* ✓ All data is standardized and validated

== Key Takeaways

* **9 steps** happen in seconds when you ask a question
* **MCP Server is the gatekeeper** at every step
* **RBAC is enforced** — you can only see/do what your AAP user allows
* **Data is standardized** — complex AAP data is simplified for the AI
* **Security first** — tokens, permissions, and audit logs protect everything
