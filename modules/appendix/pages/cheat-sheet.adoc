= MCP Cheat Sheet

A quick reference for common tasks, queries, and configurations.

== Quick Setup Commands

=== Cursor IDE (One-Time Setup)

[source,bash]
----
# 1. Add to ~/.zshrc or ~/.bashrc
export AAP_MCP_URL="https://your-aap.com:8448"
export MY_SERVICE_TOKEN="your-token-here"
export NODE_TLS_REJECT_UNAUTHORIZED=0

# 2. Reload shell
source ~/.zshrc

# 3. Open Cursor Settings → Tools & MCP
# 4. Add 6 servers with this template:
{
  "type": "streamable-http",
  "url": "${env:AAP_MCP_URL}/job_management/mcp",
  "headers": {"Authorization": "Bearer ${env:MY_SERVICE_TOKEN}"}
}
# (Change "job_management" to: inventory_management, system_monitoring,
#  user_management, security_compliance, platform_configuration)

# 5. Restart Cursor
----

== API Token Quick Reference

=== Create Token (AAP Web UI)

[source]
----
1. Log in to AAP
2. Access Management → API Tokens
3. Create API Token
4. Name: "mcp-token" (or any name)
5. Application: Leave blank
6. Scope: "Read" or "Read + Write"
7. Click Create
8. Copy token immediately (not shown again!)
----

=== Token Scopes

[%header,cols="1,3"]
|===
| Scope | Permissions
| Read | View-only access (safe default)
| Write | Can make changes (use carefully)
| Read + Write | Full access (admin only)
|===

=== Rotate Token (Security Best Practice)

[source]
----
1. Create new token with same scope
2. Update configuration in AI tool
3. Restart AI tool
4. Delete old token in AAP
----

== Troubleshooting Checklist

=== Connection Issues

[cols="1,2"]
|===
| Check | How to Verify

| URL is correct
| Paste URL in browser, should not give "refused"

| Token is valid
| Try creating new token in AAP

| Network reaches MCP
| `curl -k https://your-mcp-url`

| MCP is deployed
| Check OCP: Deployments → mcp pod running?

| AAP is accessible
| Log in to AAP web UI successfully
|===

=== Configuration Issues

[cols="1,2"]
|===
| Check | How to Verify

| Environment variables set
| `echo $MY_SERVICE_TOKEN`

| All 6 toolsets added
| "What tools are available?" should list 85+

| Bearer prefix included
| Config should have `Bearer $token` not just `$token`

| AI tool restarted
| Fully close and reopen (not refresh)

| YAML is valid
| Try different tool first to test setup
|===

=== Permission Issues

[cols="1,2"]
|===
| Check | How to Verify

| Token scope matches needs
| Read-only token can't launch jobs

| AAP user has permissions
| Check RBAC in AAP → Access Management

| Organization access
| User should be in organization to access

| Team membership
| Team-level resources require team access
|===

== Quick Debugging Steps

=== "Connection Refused"

[source,bash]
----
# Step 1: Test URL manually
curl -k https://your-mcp-url
# Should return 400/401, not "refused"

# Step 2: Check deployment
oc get deployments -n aap | grep mcp
# Should show 1/1 Ready

# Step 3: Check route
oc get routes -n aap | grep mcp
# Should show a URL in Location column

# Step 4: Try different URL format
# If using OCP, make sure NO port (aap-mcp.apps.com)
# If using RHEL, make sure WITH port (hostname:8448)
----

=== "Unauthorized" / "401"

[source,bash]
----
# Step 1: Verify token
echo $MY_SERVICE_TOKEN
# Should show 40+ character string

# Step 2: Test token
curl -k -H "Authorization: Bearer $MY_SERVICE_TOKEN" \
  https://your-mcp-url
# Should not return 401

# Step 3: Create new token
# Go to AAP → Access Management → API Tokens
# Create new token
# Update configuration

# Step 4: Restart tool
# Fully close and reopen AI tool
----

=== "Tool Not Found"

[source,bash]
----
# Step 1: List available tools
# In AI tool, ask: "What tools are available?"

# Step 2: Verify all 6 toolsets configured
# Check config for all 6 endpoints

# Step 3: Check tool name spelling
# Use exact names from "tools available" response

# Step 4: Restart tool and retry
----

## Common Configuration Errors

=== Missing Bearer Prefix

**Wrong:**
[source,json]
----
"Authorization": "${env:MY_SERVICE_TOKEN}"
----

**Correct:**
[source,json]
----
"Authorization": "Bearer ${env:MY_SERVICE_TOKEN}"
----

=== Wrong URL Format

**Wrong (OpenShift):**
[source]
----
https://aap-mcp.apps.example.com:8448/job_management/mcp
(includes port)
----

**Correct (OpenShift):**
[source]
----
https://aap-mcp.apps.example.com/job_management/mcp
(no port)
----

=== Missing Toolsets

**Wrong (only 1 server):**
[source]
----
{
  "aap-job-mgmt": {...}
}
----

**Correct (all 6 servers):**
[source]
----
{
  "aap-job-mgmt": {...},
  "aap-inventory": {...},
  "aap-monitoring": {...},
  "aap-user-mgmt": {...},
  "aap-security": {...},
  "aap-config": {...}
}
----

## Environment Variables

[%header,cols="2,3,2"]
|===
| Variable | Purpose | Example

| AAP_MCP_URL or AAP_SERVER
| MCP server location
| https://aap-mcp.apps.example.com

| MY_SERVICE_TOKEN or AAP_SERVICE_TOKEN
| API authentication
| abc123def456...

| NODE_TLS_REJECT_UNAUTHORIZED
| Skip SSL verification (demo only!)
| 0

| NODE_DEBUG
| Debug mode (verbose logging)
| *
|===

**Warning:** Only use `NODE_TLS_REJECT_UNAUTHORIZED=0` in development! Use proper SSL certificates in production.

## Useful One-Liners

[source,bash]
----
# Find MCP route URL
oc get routes -n aap -o wide | grep mcp

# Get MCP pod logs
oc logs -n aap -l app=aap-mcp --tail=50

# Check MCP pod status
oc get pods -n aap | grep mcp

# Restart MCP pod
oc delete pod -n aap -l app=aap-mcp

# Check AAP token validity
curl -k -H "Authorization: Token $MY_SERVICE_TOKEN" \
  https://your-aap-url/api/v2/ping/

# Test MCP endpoint
curl -k -H "Authorization: Bearer $MY_SERVICE_TOKEN" \
  https://your-mcp-url/job_management/mcp

# Show environment variables
env | grep -E "(AAP|TOKEN|MCP)"
----
