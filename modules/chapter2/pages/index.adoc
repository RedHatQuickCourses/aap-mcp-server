== The Problem We're Solving

=== Current Situation (Without MCP)

When a playbook fails, operations teams typically:

[%hardbreaks]
1. **Get alerted** - Error message appears in logs
2. **Search for solution** - Google, Stack Overflow, docs (5-15 min)
3. **Diagnose the problem** - Check configs, variables, versions (10-20 min)
4. **Write a fix** - Update playbook or configuration (10-20 min)
5. **Test the fix** - Run playbook in test environment (10-20 min)
6. **Apply to production** - Deploy the fix carefully (5-15 min)
7. **Verify success** - Monitor for any new issues (5-10 min)

**Total time: 1-2 hours per error** (sometimes much longer for complex issues)

This is **reactive**, **manual**, and **inefficient**.

=== New Situation (With MCP + Claude)

With MCP and Claude:

[%hardbreaks]
1. **Error is captured** - Automatically, with full context (<5 sec)
2. **Claude analyzes** - AI examines error and generates fix (<30 sec)
3. **Operator reviews** - Human reviews Claude's solution (1-2 min)
4. **Fix is applied** - Automatically with backup created (<5 sec)
5. **Playbook retries** - Continues from failure point (varies)
6. **Success verified** - Automatic verification (<5 sec)

**Total time: 2-5 minutes per error** (including operator review)

This is **proactive**, **automated**, and **efficient**.

== How It Works: The Five-Step Workflow

[%hardbreaks]
.Step 1: Error Occurs
Your Ansible playbook runs and a task fails. The system immediately captures:
- Task name and which module failed
- Complete error message
- All variables and environment info
- Ansible version and logs
- Timestamp and affected hosts

.Step 2: Error Sent to Claude via MCP
The error context is sent to Claude API through MCP. Claude receives structured information about:
- What failed and why
- The context in which it failed
- Recent configuration state
- Historical patterns (if available)

.Step 3: Claude Analyzes & Provides Solution
Claude examines the error and provides:
- **Root Cause Analysis** - Why did this fail?
- **Explanation** - What does this error mean?
- **Fixed Code** - Here's the corrected configuration
- **Apply Steps** - Here's how to apply the fix
- **Prevention Tips** - How to avoid this in future

.Step 4: Operator Reviews & Approves
A human operator sees:
- Clear explanation of the problem
- Proposed fix with a diff showing changes
- Risk assessment (will this break anything?)
- Claude's confidence score
- Then clicks "Approve" or "Reject"

.Step 5: Fix Applied Automatically
Once approved, the system:
- Creates a backup of original files
- Validates the fix syntax
- Applies the fix atomically
- Retries the playbook
- Logs everything for audit trail

== Why MCP is Critical

Without MCP:
* Claude would need manual description of error (no automation)
* Operator would need to copy-paste error messages (error-prone)
* No structured communication between systems (inefficient)
* Each AI tool would need custom integration (duplicated work)

With MCP:
* Error automatically structured and sent
* All necessary context included automatically
* Standard protocol works with any MCP-compatible tool
* Claude has complete situational awareness
* System can make informed decisions
