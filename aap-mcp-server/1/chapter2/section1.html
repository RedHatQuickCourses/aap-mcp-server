Mcp Server for playbook error detection and resolution.

This brief will demonstrate how the MCP server can be leveraged to identify errors in Ansible playbooks, use Claude to analyze the issues and recommend appropriate resolutions, and then automate the remediation process. To ensure the changes are applied in a controlled and governed manner, the Automation Orchestrator approval workflow can be integrated to provide a human-in-the-loop validation step before the fix is automatically implemented.

Lab Scenario: Hello World Sample with Error

We’ll use a simple but intentional error to demonstrate the system:

---
- name: Hello World Sample
  hosts: all
  tasks:
    - name: Hello Message
      debug:
        msg: "Hello World"

    - name: APP version
      debug:
        msg: "{{ app_version }}"

we created a file hello-world-playbook.yml with the above content. The second task references a variable app_version that is not defined anywhere, which will trigger an error when the playbook is executed. This will allow us to observe how MCP captures the error and a prompt to Claude analyzes it.

In AAP Controller:

  2. Find MCP-Error-Detection-Lab

  3. Click the Launch button (play icon)

  2. Now give a Prompt to Claude to analyze the error. The system will automatically send the error context to Claude for analysis. Within 30 seconds, you will receive a proposed solution.

  3. The output can be different from the following example, but it should look similar and the resolution would be to add the aap_version.

Step 6.2: Alternate fix option:

The applied fix (visible in job output or GitHub):

# Original (with error):
- name: APP version
  debug:
    msg: "{{ app_version }}"

# Fixed by Claude (auto-applied):
- name: APP version
  debug:
    msg: "{{ app_version | default('1.0.0') }}"

# Or with explicit variable:
vars:
  app_version: "1.0.0"

Step 6.3: Verify in GitHub
